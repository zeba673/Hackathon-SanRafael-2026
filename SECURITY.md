# Herramientas y uso seguro

Esta guía reúne los recursos que pueden ayudarnos durante las prácticas y establece cómo utilizarlos de forma segura. No es obligatorio usar todas las herramientas: cada equipo puede elegir las que mejor se adapten a su tarea.

> [!IMPORTANT]
> Antes de incorporar imágenes, sonidos, modelos, código o cualquier otro recurso al juego, revisá su licencia y guardá la atribución correspondiente cuando sea necesaria.

## Recursos para el juego

### [Kenney](https://kenney.nl/)

Biblioteca de recursos para videojuegos con sprites, interfaces, modelos, audio y kits iniciales. Es útil para crear prototipos rápidamente y concentrarnos primero en las mecánicas del juego.

**Puede ayudarnos con:**

- arte 2D y 3D para prototipos;
- iconos y elementos de interfaz;
- recursos de audio;
- kits de inicio para distintos tipos de juego.

### [Sonniss](https://sonniss.com/)

Plataforma especializada en efectos de sonido y bibliotecas de audio para videojuegos y proyectos audiovisuales. Puede servir para buscar ambientes, impactos, movimientos y otros sonidos que mejoren la experiencia del juego.

**Puede ayudarnos con:**

- efectos de sonido;
- ambientes y paisajes sonoros;
- material de referencia para el equipo de audio;
- paquetes de audio para prototipos.

> [!NOTE]
> Las condiciones de uso pueden variar entre bibliotecas o paquetes. Hay que comprobar la licencia de cada descarga antes de subirla al repositorio.

## Organización y diseño colaborativo

### [Miro — Lluvia de ideas](https://miro.com/es/lluvia-de-ideas/)

Pizarra visual online para organizar ideas en equipo. Podemos usarla al definir el concepto del juego, ordenar propuestas, diseñar flujos y registrar decisiones antes de comenzar a programar.

**Puede ayudarnos con:**

- lluvias de ideas;
- mapas mentales y diagramas;
- organización de mecánicas y tareas;
- referencias visuales y planificación compartida.

## Inteligencia artificial para desarrollo

Las herramientas de IA son asistentes: el equipo sigue siendo responsable de comprender, probar y revisar todo lo que se incorpora al proyecto. No se deben compartir contraseñas, datos personales, documentos privados ni información sensible en los prompts.

### [Claude Code](https://claude.com/product/claude-code)

Asistente de programación con acceso al contexto del proyecto. Puede leer el código, modificar archivos, ejecutar comandos y ayudar a desarrollar funcionalidades, corregir errores o automatizar tareas.

### [OpenAI Codex](https://chatgpt.com/es-ES/codex/)

Agente de programación que puede colaborar en tareas de desarrollo de software, como explorar un repositorio, editar archivos, ejecutar pruebas y revisar cambios. Resulta útil para implementar tareas delimitadas y documentar el trabajo realizado.

### [Google Antigravity](https://antigravity.google/)

Plataforma de desarrollo orientada a agentes. Incluye opciones para trabajar desde un entorno de desarrollo, la terminal y un administrador de agentes, por lo que puede ayudar a organizar y ejecutar tareas de programación asistidas por IA.

## Skill recomendada para programar

### [Ponytail](https://github.com/DietrichGebert/ponytail)

Conjunto de instrucciones y skills para asistentes de programación que prioriza soluciones simples, reutiliza lo que ya existe y evita agregar dependencias o abstracciones innecesarias. Puede utilizarse como apoyo para mantener el código del proyecto claro y fácil de revisar.

Su enfoque es útil para:

- reducir la sobreingeniería;
- reutilizar funciones y recursos existentes;
- preferir herramientas nativas antes de sumar dependencias;
- implementar únicamente lo necesario para completar una tarea;
- revisar cambios y detectar complejidad innecesaria.

> [!TIP]
> La instalación depende del asistente de IA que utilice cada integrante. Consultá las instrucciones del repositorio de Ponytail y, si tenés dudas, preguntá antes de incorporarlo al flujo de trabajo.

## Criterios de uso

1. Confirmar que la herramienta sea adecuada para la tarea.
2. Revisar licencias, permisos y condiciones de uso.
3. No compartir información privada o credenciales.
4. Verificar manualmente cualquier resultado generado por IA.
5. Probar el cambio en Godot antes de abrir un pull request.
6. Registrar en el pull request los recursos externos y herramientas relevantes que se hayan utilizado.
